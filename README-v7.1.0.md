# Surnia v7.1.0 — "Proven Change": أول وكيل لا تحتاج أن تثق به

**Built directly on the user's v7.0.0 base (nothing reverted — every v7.0 power is intact).**
v7.0 جعل الوكيل يجمع الأدلة. v7.1 يجعله **يُثبت**: كل إصلاح يمر عبر بوابات لا تستطيع النماذج التحدث معها.

---

## 1. الرأس الإعلاني: التغيير المُثبَت (Proven Change)

الوكيل لا يقول «انتهيت» — بل يثبتها عبر خمس حلقات صلبة، كلها داخل الـ harness لا داخل النموذج:

### 1.1 بوابة الطفرات على الأسطر المتغيّرة (mutation gate)
- الطفرات تُولَّد **فقط على الأسطر التي عدّلها الوكيل فعلاً** (من سجل الأدلة، مع اشتقاق `git diff -U0` عند غياب المدى).
- عوامل الطفرات الحقيقية: `>` ↔ `>=`، `<` ↔ `<=`، `===` ↔ `!==`، `&&` ↔ `||`، **`+=` ↔ `-=`** (صنف خلل التراكمي — يصطاد «الجمع صار طرحًا»)، `return true` ↔ `false`، **حذف الشرط** (`if (x)` → `if (true)`)، نط الخواص الرقمية، إتلاف الثوابت النصية.
- كل طفرة تُكتب على القرص، تُشغَّل حزمة الاختبارات، ثم **تُستعاد البايتات الأصلية دائمًا** (finally، حتى مع throws، حتى بدون git).
- الحكم **معدل قتل** لا استقصاء واحد: `killed/ran ≥ 70%` و`killed ≥ 3` → PROVEN؛ الناجون يُعادون كأدلة محددة («سطر 42 من src/auth.ts ما زال يمر مع قلب `>`») تُطعَم للوكيل كتوجيه إصلاح.
- الحكم الصادق في كل الحالات: baseline أحمر → INCONCLUSIVE (لا تهمة زور)؛ عينة صغيرة بنسبة قتل 100% → «STRONG (small sample)» لا «أضف اختبارات» — **الرسالة نفسها لا تكذب**.

### 1.2 كاشف الاختبارات المزيفة — قطعي، بلا نموذج (fake-test gate)
قواعد AST-lite تُشغَّل قبل الناقد، صفر استدعاءات نموذج:
- **JS/TS**: `expect(true).toBe(true)`، `expect(lit).toBe(nفس lit)`، `expect(x).toBe(x)`، `it.skip/xit/xdescribe/it.todo`، **جسم اختبار بلا أي assertion** (مسح كتلي بحدود الأسطر)، `catch {}` فارغ، ملف كل `expect()` فيه على mocks فقط.
- **Python**: `assert True/1`، `assertEqual(True, True)`، `assert x == x`، `@unittest.skip`/`pytest.mark.skip`، `except …: pass` (بما فيها الشكل متعدد الأسطر)، دالة `test_*` بلا assert.
- النتائج تُطعَم مباشرة للوكيل **و**لناقد النموذج.

### 1.3 الأحمر ← الأخضر مفروض من السجل (harness-enforced red→green)
- كل أمر اختبار ينفّذه الوكيل (run_command / test_run / auto-verify) يُسجَّل في **سجل اختبارات** مع تحليل نتائج كل اختبار (jest/vitest PASS/FAIL، pytest ids، ✔/✖).
- الحكم من السجل لا من النثر: **يجب أن يسبق تشغيل فاشل (أحمر) تشغيلًا ناجحًا (أخضر)** لنفس الأمر — الترتيب بحسب موضع الإدخال (لا تنقلبه الملي ثانية المشتركة).
- **كشف الانحدار**: أي اختبار نجح «قبل» وفشل «بعد» يُسمّى بالاسم ويُعلَم انحدارًا — ليس إصلاحًا.

### 1.4 ربط الادعاءات بالأدلة (claim→evidence audit)
- كل جملة في التقرير النهائي تُفحص آليًا مقابل سجل الأدلة («عدّلت X» → X في سجل الملفات الملموسة، «شغّلت الاختبارات» → تشغيل مسجل، الأفعال العربية والإنجليزية) — ما لا دليل له يُعلَّم في البطاقة.

### 1.5 حزمة الإثبات الموقعة القابلة لإعادة التشغيل (proof package)
- ملف `surnia-proof-*.json` يضم: **بصمات sha256 لكل ملف قبل/بعد** (الهاش «قبل» يُلتقط قبل أول تعديل فعلي — بلا سباق)، كل الأوامر مع أكواد الخروج، تشغيلات الاختبار، نتيجة الطفرات مع الناجين، كاشف الوهمي، تدقيق الادعاءات، حكم الناقد، وأسوار البوابات.
- **التوقيع HMAC-S256** على canonical JSON — أي تعديل أي حقل يُبطل التوقيع (timing-safe compare).
- **`surnia verify <file> --rerun`**: يتحقق من التوقيع، يقارن البصمات مع الشجرة الحالية (كشف drift)، ويعيد تشغيل أمر الاختبار نظيفًا ويقارن الخروج — فيصبح تعليق الـ PR شيئًا يتحقق منه المراجع بنقرة.
- `proofToMarkdown()` يولّد **تعليق PR جاهز اللصق** (جدول البوابات + بصمات الملفات + الأوامر).

### 1.6 المقياس المنشور: False-Done Rate
> نسبة التشغيلات التي أعلن فيها الوكيل النجاح فنقضتها البوابات — تُحسب كل تشغيل، تُعرض في الواجهة، وتُنشر. هذا هو العنوان: **«أول وكيل لا تحتاج أن تثق به»**.

القيود الصريحة (مذكورة حتى لا نَعِد أكثر مما نُنفِّذ): الطفرات بطيئة (لهذا على الأسطر المتغيّرة فقط، بميزانية زمنية)، وتضغط على الاختبارات لا على صحة المواصفة نفسها.

## 2. حلبة بحَكَم موضوعي ودمج مُتحقَّق منه (Arena 2)

إعادة بناء كاملة (ليست ترقية) — الحَكَم **أرقام لا رأي نموذج**:
- **محاولات متوازية** (سقف تزامن 3) — كل محاولة في worktree مع **بيئة معزولة**: نطاق منافذ خاص، `DATABASE_URL` sqlite خاص، ونسخ `.env` من الجذر (فجوة بيانات الاعتماد المعروفة في worktrees).
- **الدرجة 0–100**: اختبارات 40 + قتل الطفرات على أسطر المحاولة 30 + lint نظيف 10 + ملاءمة حجم الفرق 20 — والناقد عبر العائلة المزوّدة بونص مستقل حتى 10 **يُعرض منفصلًا** كي يبقى عمود الأرقام بلا نموذج.
- **الدمج المُتحقَّق منه**: دمج على مستوى الملف من أفضل محاولتين، ثم **إعادة اختبار في مساحة العمل الأم** — لا يُقبل الدمج إلا إذا بلغ درجته ≥ أفضل محاولة منفردة، وإلا يُرفض وتُستعاد الشجرة.
- لوحة سباق حية (تحديثات دفع لحظية `kdx:arena-update`) + سجل محفوظ (آخر 50 سباقًا).

## 3. منقّح حقيقي للوكيل (DAP)

عميل Debug Adapter Protocol أصيل فوق TCP بترميز Content-Length:
- **python** عبر debugpy (تثبيت تلقائي بنقرة) و**node** عبر `@vscode/js-debug` `dapDebugServer` (تثبيت بنقرة).
- أدوات الوكيل: `debug_start` (launch + breakpoints + pause)، `debug_state` (الموقع + المتغيرات الحية)، `debug_eval` (تقييم تعبير في الإطار الأعلى)، `debug_step` (continue/next/stepIn/stepOut مع watches)، `debug_stop` (مسار أدلة **السبب الجذري**).
- كل حالة توقف (الموقع + المتغيرات + التقييمات) تُسجَّل كأدلة سبب جذري تُرفَق بحزمة الإثبات.

## 4. الأمان بتتبّع التلوّث (taint-aware approvals)

- كل محتوى يدخل السياق من خارج لوحة مفاتيح المستخدم يوسَم **ملوَّثًا** مع مصدره: web_fetch، نتائج MCP، ملفات المستودع (README/docs/issue templates)، مهارات مستوردة.
- أي أمر في صنف خطر (تنفيذ/شبكة/تثبيت/نشر/إتلاف) يصدر **بينما التلوث نشط** يُرفع إلى **موافقة صريحة حتى في fullAccess**، والبطاقة تعرض مصادر التلوث الحية — جدار الحقن طلبٌ للنموذج؛ هذه بوابةٌ للأمر.
- **فاحص التسمم ممتد**: قواعد حقن المستودعات (curl|sh، تعليقات HTML حاملة تعليمات، محارف صفرية العرض، preinstall hooks، طلب بيانات اعتماد) تمتد من خوادم MCP إلى **المهارات المستوردة** (حجر صحي) وملفات المستودع.

## 5. التحقق السريع بالأثر (impact-driven verification)

- `selectAffectedTests()`: تغطية (istanbul/cobertura) إن وُجدت → ثم **مخطط الاستيراد** (ملفات الاختبار التي تستورد الملفات المتغيّرة) → ثم اصطلاح الأسماء (`src/auth.ts` → `auth.test.ts` / `tests/test_auth.py`).
- `buildNarrowedCommand()`: jest/vitest/node --test/pytest تأخذ مسارات؛ **العدّاء الذي لا يضيّق يعيد الحزمة الكاملة** — التضييق لا يتجاهل اختبارات بصمت أبدًا.
- الطفرات تُحسب على الأسطر المغطاة فقط عندما تتوفر بيانات تغطية.

## 6. v7.1 على السطر الأول: العزل والمصادقة والميزانية

- **عزل OS حقيقي**: docker (حاوية لمرة واحدة، `--network none` افتراضيًا، حدود CPU/RAM، صورة `surnia-isol` تُبنى تلقائيًا) / WSL (تنفيذ داخل التوزيعة عبر ترجمة /mnt) / Windows Sandbox (توليد .wsb بلا شبكة وبلا vGPU). **مغلق عند الفشل**: لو تعذّر البروفايل، يُرفض الأمر — لا سقوط صامت إلى تنفيذ المضيف.
- **MCP OAuth**: اكتشاف RFC 8414 (+ صيغة لاحقة المسار)، تسجيل ديناميكي RFC 7591، PKCE S256، loopback callback، تخزين عبر safeStorage (0600 بديلًا)، تحديث تلقائي للتوكن — يُلصق تلقائيًا على طلبات HTTP/SSE للخوادم البعيدة.
- **ميزانية تحقق لا تستهلكها 429**: أي محاولة بوابة (مدقّق/ناقد/طفرات) تموت على 429/5xx/شبكة تُستردّ بالكامل — لا تنقص نداءات ولا دولار. الفشل القاتل (4xx) وحده يستهلك. عند النفاد: وضع الفشل الصريح (fail-closed للمهام الخطرة) — لا تخطٍّ صامت.
- **سقف تكلفة صارم للمهمة** (`agent.taskBudgetUsd`) يوقف الحلقة بلطف مع ملاحظة صريحة.

## 7. ترقية القدرات القائمة (الجدول كما وُعد)

| القدرة | كانت (v7.0) | صارت (v7.1) |
|---|---|---|
| المدقّق (verifier) | استقصاء نصي، أدلة مقروءة فقط | **يشغّل الأوامر بنفسه** (run_command + read_file في حلقة مقيدة بـ 6 خطوات عبر modelOverride)، ملفوف بالميزانية (429 مسترد) |
| الناقد (critic) | fullAccess فقط، ≥3 ملفات، نموذج أولًا | **كل الأوضاع** — الزناد خطرٌ لا وضع: ≥3 ملفات أو اختبارات مكتوبة أو باب فشل سابق؛ **القواعد القطعية أولًا** (كاشف الوهمي) ثم النموذج |
| PROOF/Artifacts | بطاقة + صفحة ثابتة | **ملف موقّع قابل لإعادة التشغيل** + تعليق PR |
| Arena/Worktrees | تسلسلي، عدّ أسطر فقط | **متوازٍ + درجات موضوعية + بيئة معزولة لكل محاولة + دمج مُتحقَّق منه** |
| المهارات (create_skill) | تُزرع وتُوثق فورًا | **بوابة أدلة**: مرشحة → تُرقّى «evidence-verified» فقط من سجل التشغيلات المسجلة (2 فشل = رجوع)؛ الفحص السام يُحجرها |
| Flows | يلاحظ تكرار الطلبات | **يتعلم من رفض المستخدم المتكرر** → يقترح قاعدة → **يتحقق بإعادة التشغيل** |
| المجدول | مؤقّتات | **محفّزات**: file-watch / webhook (loopback + token) / ci-failure (gh run list) — خلف **بوابة إثبات**: ما لم تنجح حزمة الاختبارات لا يصلك إشعار |
| فاحص تسمم MCP | خوادم فقط | **+ المهارات المستوردة + ملفات المستودع** (README/issues/docs) |
| costs.ts | تقدير تكلفة | **«تكلفة كل تغيير مُثبَت»** لكل نموذج (سجل proven.json) + **سقف مهمة صارم** |
| نقاط الاستعادة | نسخ ملفات بسقف 3000 | **التزامات ظلّية**: `git stash create` + ref `refs/surnia/checkpoints/<id>` (لا يمس الفهرس ولا الشجرة) — استعادة بـ checkout، مع **معرّف الجلسة** لعودة المحادثة مع الملفات |

## 9. التشغيل

```bash
npm install
npm run full          # typecheck + build + cli
npm test              # 125 اختبارًا
node tests/v71-e2e.mjs  # e2e حقيقي (يتطلب جسر glm-bridge)
npm run dist:win      # NSIS + zip لويندوز
```

الـ CLI: `node dist-cli/surnia.cjs "المهمة" --mode fullAccess` — و**التحقق من أي إثبات**:
```bash
node dist-cli/surnia.cjs verify surnia-proof-XXXX.json --rerun
```
