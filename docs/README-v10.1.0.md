# SADEEM v10.1.0 — «Monochrome + Quiet Lime» — إلزام التغيير

سديم v10.1.0 — نسخة التغيير الإلزامي: لغة بصرية جديدة بالكامل (نيوترال + ليموني هادئ،
صفر تدرجات، صفر إيموجي)، وتدقيق كامل لأدوات الوكيل مع تقوية توجيه تصفح الإنترنت
وسياسة لغة صريحة، وبطاقة جرد أدوات حقيقية داخل الإعدادات.

**الوكيل الذي يجب أن يُثبت أنه أنجز. / The agent that must PROVE it is done.**

---

## 1. جواب أسئلتك بالأرقام (من الكود الفعلي، لا تقدير)

> كم أداة موجودة عند الذكاء الاصطناعي؟ وهل يستخدمها كلها؟

- **عدد الأدوات المسجّلة والمُعرَضة للنموذج: 82 أداة** (`CORE_DEFS` في
  `electron/agent/tools.ts` — المصدر الوحيد الذي يشحن مع التطبيق). التوزيع:
  `fs 23 · exec 39 · meta 20` — وتُضاف إليها أدوات خوادم MCP التي يفعّلها المستخدم.
- **أدوات الإنترنت والمتصفح (13):** `web_search` · `search_web` · `web_fetch` ·
  `http_request` · `download_file` · `open_path` (يفتح أي رابط في متصفحك الحقيقي) ·
  و8 أدوات أتمتة المتصفح المدمج `browser_navigate / snapshot / click / type /
  read / screenshot / eval / close`.
- **هل كانت كلها قابلة للاستخدام؟** نعم — كل الأدوات الـ82 مسجّلة في المرسِل
  (`executeTool`) ومعروضة للنموذج عبر `getToolDefs`. **لكن** وجدنا المشكلة
  الحقيقية التي جعلتك ترى العكس: **التوجيه كان ضعيفاً** — برومبت النظام كان
  يذكر الأدوات بسطر واحد فقط، فالنماذج نادراً ما تصل إليها. v10.1 يعالج هذا جذرياً (§3).
- **الإثبات داخل التطبيق:** إعدادات ← Agent & Security ← **"Tool inventory"**
  — بطاقة مبنية من الكود وقت البناء (`scripts/gen-tool-inventory.mjs`) لا من
  نص مكتوب يدوياً، تعرض العدد الكلي وكل الأدوات بالاسم مجمّعة حسب النوع
  (`docs/ui-review/30-tool-inventory.png`).

## 3. تصفح الإنترنت — استخدامه أصبح إلزامياً على الوكيل

أضفنا لبرومبت النظام سياسة صريحة (`electron/agent/prompts.ts`):

- **"USE IT, DO NOT GUESS"** — قائمة متى يجب التصفح: (1) أي سؤال عن شيء حالي
  أو خارجي، (2) أي API/مكتبة/إصدار غير متأكد منه 100% — يتحقق من الوثائق
  الرسمية قبل كتابة الكود، (3) رسالة خطأ متكررة — يبحث بنصها، (4) مقارنة
  منتجات/أسعار/وثائق — يجلب الصفحات الحقيقية، (5) **الاستشهاد برابط المصدر**
  في إجابته عندما أتت من الويب.
- عندما تطلب "افتح/تصفح موقعاً" → `open_path` بالرابط يفتحه في **متصفحك أنت**،
  و`web_fetch` إضافياً إذا احتاج تحليل محتواه.
- أي طلب تحميل → `download_file` داخل مساحة العمل (بسقف 100MB وحارس SSRF).

### تحسينات ملموسة على الأدوات نفسها
- **web_fetch (قراءة الصفحات):** مرحلة Readability جديدة — تستخرج `<title>`،
  تحذف nav/header/footer/aside/form/svg قبل تفريغ الوسوم، وتحافظ على فواصل
  الفقرات — فيصل النص للنموذج نظيفاً ومهيكلاً بدل مزيج ضجيج.
- **حصانة حقن التعليمات:** كل محتوى الويب يبقى مُسيَّجاً كـ"بيانات غير موثوقة"
  (UNTRUSTED fence) مع دفتر taint — لم يُمسّ.

## 4. تحسين القدرات متعددة اللغات

- **سياسة لغة صريحة في برومبت النظام:** الرد بلغة المستخدم نفسها في كل النثر
  (شرح، خطط، رسائل commit، عناوين PR، ملخصات) — عربي طبيعي للعربي — مع إبقاء
  الكود والمعرفات بالإنجليزية القياسية.
- **RTL وUnicode:** تعليمات صريحة بمعالجة أسماء الملفات غير اللاتينية كمسارات
  عادية (لا إعادة تسمية ولا إتلاف)، ومحاولة ترميز صريح عند أي mojibake قبل
  الحكم على الملف.
- التطبيق نفسه ثنائي اللغة كاملاً EN/AR مع RTL (قائم من قبل، وتم تمرير لقطات
  عربية جديدة في docs/ui-review).

## 7. الحدود الصادقة

1. الملفات **غير موقّعة رقمياً** — SmartScreen سينبّه عند أول تشغيل (More info →
   Run anyway). التوقيع يتطلب شهادتك.
2. التحقق التشغيلي تم على Linux/Xvfb بنفس الكود المشحون؛ لم يُشغَّل exe على
   ويندوز حقيقي هنا — كل فحوص exe هيكلية (pefile/7zip/asar).
3. بناء الويندوز بدون Wine يعتمد ترقيع `scripts/patch-nsis.sh` (سطر واحد في
   electron-builder 26 يوجّه توليد الـUninstaller إلى قارئ JS نقي — نفس مسار
   upstream على macOS Catalina). موثّق ومتكرر.
4. بعض معرفات الكود تحمل الاسم التاريخي (`SurniaAPI`، `window.surnia`، بروتوكول
   `surnia://`، مفتاح `surnia-verify.pub`) — **عمداً**: هي واجهة برمجية بين
   preload/renderer والترحيل؛ إعادة تسميتها تكسر التوافق بلا فائدة للمستخدم.
