## 3. Every failure, ranked by user impact / كل الإخفاقات مرتّبة حسب الأثر

### I4 — S2: a fatal 402 (no credits) is silently retried 3 times

- **Observed:** 5 provider calls for one mid-run 402 (expected 2: one tool turn +
  one 402 request). The engine re-sent the same dead-account request 3 extra times.
- **Exact source (as of the final run — line numbers may drift as other agents edit):**
  - `electron/agent/engine.ts:5033` (`:5025` at the final test run; drifting as
    other agents edit the file) — `if (isInvalidKeyError(lastErr)) break;`
    breaks the retry loop **only** for 401/invalid-key. Search by that exact
    expression if the line has moved.
  - `electron/agent/providers.ts:515-517` — `isInvalidKeyError()` returns
    `providerErrorKindOf(err) === 'invalid_key'`; `no_credits` (402) is excluded.
  - Contrast `electron/agent/providers.ts:508-512` — `shouldSkipProvider()` **does**
    include `no_credits`, but the retry branch above never calls it.
- **User impact:** with default production backoff `200+400+600+800+1000+1200 ms`
  the app burns ≈4.2 s re-asking a provider that already said "no balance" before it
  shows the (correct, single-language, actionable) credits message. This is exactly the
  "كل شوي بيطلع لي خطأ / nothing happens for a bit" class of complaint — wasted time on
  a fatal, known-unrecoverable error. It is **not** a hang and the final message is fine;
  the defect is the silent retries in front of it.
- **Owner:** the engine agent (retry-loop gate) with a one-line fix direction — treat
  `no_credits` like `invalid_key` at the break point (e.g. call `shouldSkipProvider` or
  extend the fatal-kind check). This agent did **not** edit source.

No I1/I2/I3 (completion, raw-JSON, duplicate-row, proof-honesty) failures were found.

## 4. Blunt verdict / الحكم الصريح

**EN:** The AI is **not** broadly broken. In 10 of 11 nasty end-to-end cases the real
engine + real store did exactly what the founder demands: one clean completion report,
one turn-end, `running` cleared, honest proof, no raw JSON, no duplicate error rows,
no silent re-requests. Streaming (including long Arabic/Unicode), tools (bad args,
fail-then-success), aborts, 429 recovery, malformed provider JSON, compaction, subagent
failure and slow providers all passed.

The one real defect is the **402/out-of-credits path**: the engine silently retries a
fatal "no balance" error ≈3 times (≈4.2 s in production) before showing the correct
message. That is a **P2/P3 polish bug, not "the AI doesn't work"** — but it is a real,
reproducible one and it is the only thing in this matrix that still fails.

**Scope honesty:** this harness tests the **engine↔store contract with a local mock
provider**. It does not exercise real provider endpoints, the Electron IPC bridge, or
the renderer UI. So the verdict is "the engine contract is healthy except 402"; it is
not a claim that every possible user-visible error path in the whole desktop app is
covered.

**AR:** الذكاء الاصطناعي **ليس** معطلاً بشكل عام. في ١٠ من ١١ حالة اختبار حقيقية، أدّى
المحرك والمخزن المطلوب تماماً: تقرير إكمال واحد، نهاية دور واحد، حالة `running` تُفرَّغ،
إثبات صادق، لا JSON خام، لا صفوف أخطاء مكررة، لا إعادة طلب صامتة. البث (بما فيه العربي
واليونيكود)، الأدوات، الإلغاء، التعافي من 429، JSON التالف، الضغط، فشل الوكلاء الفرعيين،
والمزود البطيء — كلها نجحت.

العيب الحقيقي الوحيد هو **مسار 402 / نفاد الرصيد**: يعيد المحرك طلب خطأ "لا رصيد" قاتل
٣ مرات صامتة (≈٤٫٢ ثانية في الإنتاج) قبل عرض الرسالة الصحيحة. هذا عيب تحسين وليس
"الذكاء الاصطناعي لا يعمل" — لكنه عيب حقيقي قابل لإعادة الإنتاج، وهو الشيء الوحيد في
هذه المصفوفة الذي ما زال يفشل.

**حدود الحكم:** يختبر هذا الهارنس عقد «المحرك ↔ المخزن» مع مزود محلي وهمي. لا يختبر
نقاط المزود الحقيقية ولا جسر IPC ولا واجهة التطبيق. لذا الحكم هو «عقد المحرك سليم عدا
402»، وليس ادعاءً بتغطية كل مسار خطأ مرئي في تطبيق سطح المكتب.

## 5. How to read a future run / كيف تقرأ التشغيل القادم

- `[V1123] Sxx …: PASS (0 failures)` → case clean.
- `[V1123 FAIL] Sxx … :: [I#] <check> :: <detail> :: @<file>:<line>` → real defect;
  `I1` = hang/crash/no terminal report, `I2` = raw JSON or mixed-language error,
  `I3` = duplicate error row / dishonest proof, `I4` = silent re-request / auto-switch.
- The final `TOTAL FAILURES: n` and the ranked block are authoritative — nothing is
  suppressed. A red line must be triaged by the owning agent; do not mark the suite
  green by weakening an assertion.
