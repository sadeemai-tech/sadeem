## الحكم / Verdict

### عربي — حكم صريح

**لا، DNA لم يعد يتوقف عند رقم. V13 نزل فعلاً في هذه النسخة وأصلح السبب الجذري. لكن بقيت ثغرة واحدة حمراء.**

أثبتُّ بالأدلة المادية:

1. أربعة تشغيلات حقيقية للمحرك بحقائق **مختلفة** أنتجت أربعة أنماط في `dna.json` بالقرص (1→2→3→4)، بلا حذف صامت.
2. عند السقف (60 نمطاً) أتى تشغيل حقيقي بحقيقة **جديدة**، فبُقيت الجديدة وطُرد نمط قديم **مُعزَّز** واحد بالضبط (59 بقي)، و`factsRecorded` ظل يرتفع (60→61). العكس هو بالضبط خطأ «يتوقف عن التعلّم عند 60».
3. أدخلتُ 8 أنماط مُعزَّزة (ثقة 0.95) تملأ نافذة التوجيه، ثم حقيقة جديدة (ثقة 0.4): الحقيقة الجديدة **وصلت فعلاً** إلى الـ system prompt للتشغيل التالي داخل الـ dynamic tail غير المُخزّن مؤقتاً، ونجت من مسار إسقاط `cache_control`، وعادت من القرص في نسخة وحدة جديدة (محاكاة إعادة تشغيل) مع حدث `kdx:dna:event`.
4. السقف **معلن ومحدود تصميمياً** لا مخفي ولا كاذب: `DNA_LIMITS.maxPatterns = 60` و`DNA_LIMITS.maxFeedback = 40`، مع 4 مقاعد محجوزة للحقائق الأحدث في التوجيه، وسياسة طرد تحفظ الجديد، وعدّ تراكمي `factsRecorded` لا يتوقف عند السقف. لا يوجد ادّعاء «غير محدود» في نسخة المستخدم.

**لكن (GUARD-4 أحمر):** خطأ مزوّد **عابر واحد** أثناء الاستخراج (حدث SSE `error` مع HTTP 200) يبتلعه `learnDNAFacts` بصمت دون أي إعادة محاولة، فتضيع الحقيقة كلها في ذلك التشغيل. رصدتُ **نداء استخراج واحد فقط** — أي لا يوجد retry إطلاقاً. هذا هو الوجه الوحيد الذي ما زال «يتوقف فيه التعلّم» — لا عند رقم 60، بل عند أول هفوة شبكة.

**الخلاصة:** السؤال «هل الـ DNA ما زال يتوقف عند رقم؟» → **لا** عند السقف؛ **نعم** عند أول خطأ عابر. V13 أصلح البنية (سقف صادق، طرد بلا فقدان، حقيقة جديدة تصل للتوجيه، محاكاة إعادة تشغيل، سجل نمو تراكمي)، لكن متانة الاستخراج ما زالت ناقصة. أغلق F1 أدناه ثم أعد التشغيل: إذا ظهر `ALL-GUARDS-PASS` فالحكم النهائي «لا، لا يتوقف عند رقم — لا عند السقف ولا عند هفوة».

### English — blunt verdict

**No — DNA no longer "stops at a number". V13 has landed in this source tree and fixed the root cause. One gap is still red.**

Proven with physical artifacts:

1. Four REAL engine runs with **distinct** new facts produced four patterns in `dna.json` on disk (1→2→3→4) — nothing silently dropped.
2. At the **60-pattern cap**, a real-engine NEW fact was **kept** and exactly one OLD **reinforced** pattern was evicted (59 left), while `factsRecorded` kept climbing (60→61). The reverse — dropping the new, low-confidence fact — was the original "stops learning at 60" bug.
3. I pre-filled the render window with 8 reinforced patterns (confidence 0.95) and then learned one new fact (0.4): the new fact **still reached** the next built system prompt's uncached dynamic tail, survived the no-`cache_control` downgrade, and reloaded from disk in a **fresh module instance** (restart simulation), with `kdx:dna:event` reaching the renderer.
4. Caps are **honest and bounded by design, not hidden**: `DNA_LIMITS.maxPatterns = 60`, `DNA_LIMITS.maxFeedback = 40`, 4 prompt slots reserved for the newest facts, lossless eviction, and a cumulative `factsRecorded` that does not plateau at the cap. No "unlimited" claim in product copy.

**But (GUARD-4 red):** ONE transient provider error during extraction (an SSE `error` event over HTTP 200) is swallowed by `learnDNAFacts` with no retry at all — I observed exactly **one** extraction call — so the whole learning event is lost for that run. That is the only remaining way learning "stops": not at number 60, but at the first network hiccup.

**Bottom line:** "Does DNA still stop at a number?" → **No at the cap; yes at the first transient error.** V13 fixed the architecture (honest bound, lossless eviction, new facts reach the prompt, restart survival, cumulative growth). Extraction resilience is still missing. Close F1 below and re-run: `ALL-GUARDS-PASS` then means "no — it does not stop, neither at the cap nor at a hiccup."

## السقوف — صادقة / The caps — honest

- `DNA_LIMITS.maxPatterns = 60` (`electron/agent/dna.ts:53-68`) — the **active window** is bounded because it is injected into a system prompt. `capPatternsLossless` (`dna.ts:412-421`) evicts the highest "forget" patterns (most reinforced, then oldest) and **keeps every newly learned fact** (`dna.ts:502`). Bounded ≠ frozen.
- `DNA_LIMITS.maxFeedback = 40` (`dna.ts:61`) — recent feedback is trimmed newest-first (`dna.ts:528`). This is a 40-feedback cap, stated plainly — not an "unlimited" promise.
- `DNA_LIMITS.promptNewPatterns = 4` (`dna.ts:66`) — of the 8 rendered patterns, 4 are reserved for the most recently **first-seen** facts, so a new low-confidence fact can never be crowded out by 8 reinforced ones. This is the core V13 prompt fix.
- `dedupeKey` (`dna.ts:385-390`) now keys on the FULL normalized text (≤240 chars) instead of a 48-char prefix — two genuinely different facts that start alike are no longer silently merged.
- `stats.factsRecorded` is cumulative and the growth chart plots `facts` (`dna.ts:358-372,718-747`) — so `/dna` cannot visually flatten at 60 and fake "stopped learning".
- `renderDNAPrompt` emits an honest `LEARNING STATUS: N facts recorded … showing M of K active patterns` plus a `CONTINUOUS LEARNING` directive (`dna.ts:654-675`). Honest numbers, no "unlimited" wording.
- `dna-stats.json` keeps a bounded 14-day growth series (`dna.ts:73,358-372`).
